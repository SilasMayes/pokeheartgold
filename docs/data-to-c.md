# Data tables converted from asm

Generated by `tools/s2c.py --report`. 2258 objects from 82 asm files, in 317 C files under `src/data/`; 1703 have the type the C code declares (or the type a typed pointer to them has), the rest are written from the asm directives: byte, halfword and word arrays, pointer tables, and anonymous structs where pointers and numbers mix.

To redo the conversion, check out the commit before it and run

    python3 tools/s2c.py --verify --mwcc <metroskrew>/bin --install --report docs/data-to-c.md asm/*.s lib/asm/spl_data.s lib/NitroDWC/asm/dwc_lobby_data.s

Checks, for HeartGold and SoulSilver:

- `--verify`: each file compiled with arm-none-eabi-gcc matches the original assembled by arm-none-eabi-as (bytes, relocations, symbol offsets and binding). This is the check of the contents.
- `--mwcc BINDIR` (metroskrew's native mwccarm/mwasmarm): the C files compiled with MWCC, with the Makefile's flags, and laid out as the linker places them, match the original assembled by MWAS exactly: bytes, relocations, symbol offsets, section sizes and alignment. The final check is the ROM build itself.

## Why some asm files became several C files

MWCC does not keep definition order. It puts a file's objects in one list (the .bss ones in definition order, then the initialised ones in reverse definition order), sorts that by size with MSL's heapsort, and gives each one-dimensional char array a section of its own while everything else of a kind shares one section. The linker then starts every section 4-aligned (`ALIGNALL(4)` in the SDK's LCF templates). One C file can therefore only produce runs of objects sorted by size, and a char array off a 4-byte boundary cannot have a section of its own. Most asm data files cover several original files, so s2c cuts each section into the fewest runs one file can produce, puts run k of every section into file k, and picks the definition order that makes the heapsort put every object where the asm has it (`plan_tus`, `mw_definition_order`). Char arrays that have to share a section with their neighbours are written as the only row of a 2-D array (`u8 x[1][N]`). Keep the order when editing these files, or rerun s2c.
